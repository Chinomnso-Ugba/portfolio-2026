Weather App

A small weather app that searches any city and shows current conditions, built to practise working with a third-party API.

Role
Design and development
Built
July 2025
Stack
HTML, CSS, JavaScript, OpenWeatherMap API
Live site (opens in a new tab) Source code (opens in a new tab)

Overview

This was my first project built around a real API. The goal was to take live data from an outside service and turn it into an interface that is clear at a glance.

It is a single HTML file with plain JavaScript, with no libraries.

What it does

  • Search for a city with the button or the Enter key.
  • Show the temperature, a short description, an icon and the humidity.
  • Switch between °C and °F.
  • Show a loading state while waiting and an error message if the city is not found.
  • Remember the five most recent searches as buttons that run the search again.
  • Change the card's look for clear, cloudy, rainy, snowy and stormy weather, and remember light or dark theme.

How it works

A search sends the city name and the chosen units to the OpenWeatherMap current-weather endpoint. The response is turned into text for the page, and the weather type picks a CSS class for the card.

Recent searches are kept in an array: each name is tidied and capitalised, any earlier copy is removed, the newest goes first, the list is cut to five, and it is saved to localStorage.

The tricky parts

Three states, one card

The card is either loading, showing a result or showing an error. Switching them with classes meant the page never showed a half-updated mix.

Changing units

Switching between °C and °F asks the API again for the same city, so the numbers always come from the source instead of being converted by hand.

A tidy history

Recent searches need cleaning, so "lagos" and "Lagos" are one entry, and the list stays short and saved between visits.

What I would improve

  • Send requests through a small serverless function so the API key never reaches the browser.
  • Encode the city name in the request, and show different messages for "city not found", network errors and rate limits instead of one generic message.
  • Add a five-day forecast and a "use my location" option.
  • Announce results and errors to screen readers, and label the search field properly.
  • Show the temperature, wind and rain together in a small chart.
