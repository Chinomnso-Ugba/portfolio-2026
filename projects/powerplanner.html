PowerPlanner

A mobile-first estimator that turns a list of appliances into a daily, monthly and yearly electricity cost.

Role
Design and development
Built
July 2025
Stack
HTML, CSS, JavaScript
Live site (opens in a new tab) Source code (opens in a new tab)

Overview

Electricity cost is a regular household concern in Nigeria, and it is hard to tell which appliances matter most. I built PowerPlanner so you can list what you use and quickly see the energy and cost behind it.

It is a single-page app written in plain HTML, CSS and JavaScript, designed for phones first.

What it does

  • Add and remove appliances, each with a name, a power rating in watts and daily hours of use (0 to 24, in half-hour steps).
  • Totals update as you type, with energy in kWh and cost shown together.
  • Switch between daily, monthly and yearly views.
  • Show the cost in naira, dollars or euros, using a live exchange rate with fixed fallback rates if the request fails.
  • Light and dark themes, and a layout that stacks on small screens.

How it works

Each appliance's daily energy is its wattage divided by 1,000, multiplied by the hours used. The app adds these up, then multiplies by 30 for a month or 365 for a year.

Cost is the energy multiplied by a flat rate set in the code (baseRateNGN), converted to the chosen currency with the latest exchange rate. Rates are requested once when the page loads.

The tricky parts

Keeping totals in sync

Every card can change at any time, so the app recalculates from all the cards whenever an input changes or a card is removed, instead of trying to track changes one by one.

Currency that can fail

The exchange-rate request can fail or be slow, so the app starts with fallback rates and only replaces them when a response arrives. It never shows an empty result.

Dynamic cards

New appliance cards are built from a template string and read back by position. It works, but it is fragile, and it is the first thing I would change.

What I would improve

  • Replace the flat rate with tariff bands, or let users enter their own rate per kWh.
  • Save appliances in the browser so the list survives a refresh.
  • Make it accessible: link each label to its input, announce the totals to screen readers, and add clear focus styles.
  • Replace inline event handlers with proper component state. A React and Tailwind rebuild, PowerPlanner v2, is planned.
  • Let users choose how many days make a month instead of always using 30.
